# super-AGENT

> 「主代理派发 → 子代理并行 → 主代理核验」的第二组实测：换了任务集、换了机器，1.82× 的加速比和上次的 2.01× 对得上。

## 这个仓库是什么

不是框架，也不是 SDK。是一次实验的完整留档，随时可复跑：

| 目录 | 内容 |
|---|---|
| `prompts/` | 派给子代理的提示词原文，可直接复用 |
| `workflows/` | DSH 工作流脚本，一次调用跑完 3 轮对照 |
| `scripts/` | 不依赖 DSH 的独立核验命令 |
| `results/` | 原始数据、时间戳、结论、踩过的坑 |

运行环境是 DeepSeek Harness 的 `workflow` / `subagent` 能力。没有它也能看懂结论，只是复现不了并行那一步。

## 实验设计

4 个互不相关的任务，同一时刻派发，各自独立上下文；对照组做**完全相同的 4 件事**：

| 编号 | 任务 | 数据源 | 类型 |
|---|---|---|---|
| T1 | vscode 最新正式发布 | GitHub API | web |
| T2 | Node.js 最新 LTS | nodejs.org/dist | web（大 JSON） |
| T3 | npm typescript latest | npm registry | web（小 JSON） |
| T4 | CPU / 核数 / C: 可用空间 | 环境变量 + DriveInfo | 本机 |

- **串行组**：1 个子代理顺序做完 4 项
- **并改组**：4 个子代理各做 1 项
- 各跑 3 轮，交替进行（P,S,P,S,P,S），避免时段性网络波动单向污染某一组

## 实测（2026-11-07）

| 轮次 | 串行墙钟 | 并行墙钟 | 加速比 |
|---|---|---|---|
| 1 | 31.23 s | 17.46 s | 1.79× |
| 2 | 39.03 s | 21.23 s | 1.84× |
| 3 | 31.82 s | 13.47 s | 2.36× |
| **中位数** | **31.82 s** | **17.46 s** | **1.82×** |

24 条结果全部与我独立复核的源头值一致。完整数据见 [`results/benchmark-2026-11-07.md`](results/benchmark-2026-11-07.md)。

## 三条要点

**1. 加速比的上限是 `Σt / max(t)`，不是 n。**
并行墙钟减掉最慢一路，固定开销稳定在 4.8–6.0 秒（四路子代理的启动、派发、回收）。本实验四路长短不均，理论上界只有 1.96 / 2.09 / 2.59，实测 1.79 / 1.84 / 2.36——**已经贴着上限，并行本身没有浪费**。

**2. 子代理自报的耗时系统性偏低，最多差 17.2 秒。**
串行组自报 20.6–23.4 s，墙钟 31.2–39.0 s。差额在两头：派发后的前导（1.7–3.2 s）和结果收尾（8.0–14.5 s，输出越长越慢）。只信自报数字会算出 ~1.4×，比真实值低三成。**计量口径要放在调度器侧。**

**3. 环境能力探测比提示词措辞更重要。**
本机有三条静默限制：WMI 被拒、.NET TLS 拿不到凭证、`Get-PSDrive` 返回 0。第三条最阴——它不报错，只返回 `0.0 GB`，子代理会如实上报一个 `status: ok` 的假答案。第一次跑就是这么废掉的。绕法：环境变量、Node 自带 OpenSSL、`DriveInfo`。

## 核验，不是转发

子代理返回的是**主张**，不是**事实**。核验脚本绕过所有代理直接问源头：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

一个具体教训：C: 可用空间在同一场实验的 4 分钟内从 110.20 漂到 110.14 GB（实验自己在写文件）。核验如果事后跑、又用严格相等比对，会把正常漂移误判成「子代理编数」。**核验要带时间窗。**

## 复现

### 方式一：DSH 工作流（完整复现）

1. 安装并启动 DeepSeek Harness；
2. 把 `workflows/benchmark.js` 整段内容作为 `workflow` 工具的 script 提交；
3. 脚本会跑 3 轮 P,S 交替，返回带时间戳的结构化 JSON。

### 方式二：只跑核验（不需要 DSH）

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

这条命令直接向源头要数据，不经过任何代理——它就是「交叉核验」这一步本身。

## 这个实验没有证明什么

- **没测 n > 4**。8 路、16 路的加速比是推断，不是本次数据。
- **没测 token 成本**。并行省的是墙钟和父上下文，4 个子代理各自都在烧 token。
- **没测长上下文下的隔离收益**。串行组后段有变慢的倾向，但 3 轮样本不足以定论。
- **样本仍小**。3 轮 × 2 组，中位数挡得住单轮噪声，挡不住系统性偏差。

## 与上一组实验的关系

同一套方法在另一台机器、另一组任务上测到 **2.01×**（[superagentluodiji](https://gitee.com/UnderNinePlaces/superagentluodiji)）。两次独立测量落在同一量级，说明 1.8–2.0× 是这个任务形态下的稳定值，不是单次运气。
