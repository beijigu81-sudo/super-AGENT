## 三个结论

### 1. 并行墙钟 ≈ 最慢一路 + 固定开销，固定开销是 4.8–6.0 秒

```
轮次 1：17.46 − 11.5 = 5.96 s
轮次 2：21.23 − 15.7 = 5.53 s
轮次 3：13.47 −  8.7 = 4.77 s
```

这条固定开销与代理数量无关：它买到的是四次子代理的启动、派发和结果回收。**所以加速比的上限不是 n，是 Σt / max(t)**；本实验四路长短不均，理论上界只有 1.96 / 2.09 / 2.59，实测 1.79 / 1.84 / 2.36，贴着上限——并行本身没有浪费。

### 2. 子代理自报的耗时系统性低估真实墙钟，最多差 17.2 秒

| 轮次 | 串行自报 | 串行墙钟 | 差额 |
|---|---|---|---|
| 1 | 23.4 | 31.23 | +7.8 |
| 2 | 21.8 | 39.03 | +17.2 |
| 3 | 20.6 | 31.82 | +11.2 |

差额由两段组成，都不在子代理的计时区间里：

- **前导**：从派发到它真正敲下第一个 `Get-Date`，1.7–3.2 s；
- **收尾**：从它最后一个任务结束到结构化结果返回主代理，8.0–14.5 s。

收尾这段最反直觉：**输出体积越大，收尾越慢**。第 2 轮串行子代理的 evidence 写得最长，收尾 14.5 s。如果你只信子代理自报的 `total_seconds`，会算出 ~1.4× 的加速比，比真实值低三成。**计量口径要落在调度器侧，不能落在被调度者侧。**

### 3. 加速比来自「把 N 次模型往返折叠成 1 次」，不是工具本身快

四路里真正耗时的不是 HTTP 请求，是模型往返：单个 fetch 的返回只要几百毫秒，但从「决定调用」到「拿到结果再决定下一步」要好几次往返。并行组把这 4 条串行的往返链**重叠**成 1 条，收益就在这里——所以加速比主要由「一趟往返有多贵」决定，而不是由「工具执行有多快」决定。

至于串行组后段是否被上下文拖慢：三轮里 T1 分别 3.2 / 3.5 / 3.5 s，T4 分别 0.0 / 3.8 / 6.3 s，同一轮内**并不单调**（第 2 轮几乎持平）。这个倾向能看见，但 3 轮样本不足以定论，不写成结论。

## 核验（主代理独立复核，24 条主张全部命中）

`scripts/verify.ps1` 绕过所有子代理，直接问源头：

| 主张 | 独立核验 | 结论 |
|---|---|---|
| vscode 最新正式版 `1.145.2`，`2026-11-06T10:21:07Z` 发布 | GitHub API 同字段逐项比对 `prerelease=false` | 一致 |
| Node.js 最新 LTS `26.13.0`（Lithium，2026-10-28） | `index.json` 取 `lts !== false` 第一条，跳过 `v27.0.0-alpha` | 一致 |
| npm `typescript` latest `7.0.2` | registry `version` 字段 | 一致 |
| CPU `Intel64 Family 6 Model 154 Stepping 3`，12 逻辑核 | 环境变量直读 | 一致 |
| C: 可用 `110.14–110.2 GB` | `DriveInfo.AvailableFreeSpace` | 一致（**有漂移**，见下） |

**一个必须记下来的细节**：C: 可用空间在同一场实验的 4 分钟内从 `110.20` 漂到 `110.14 GB`（因为实验本身在写文件）。如果核验脚本事后才跑、又用严格相等去比对，会把这种正常漂移误判成「子代理编数」。**核验要带时间窗，或者只比数量级。**

## 环境坑（比结论更值得抄走）

这台机器上一共有三条静默限制，它们不报错、只给假数据或假失败：

| 限制 | 表现 | 绕法 |
|---|---|---|
| WMI/CIM 被沙箱拒绝 | `Get-CimInstance` / `Get-Volume` → 「拒绝访问」 | 环境变量 + `[System.IO.DriveInfo]` |
| .NET TLS(schannel) 拿不到凭证 | `Invoke-RestMethod` / `Invoke-WebRequest` → 「基础连接已经关闭」 | Node.js 自带 OpenSSL 栈；`git -c http.sslBackend=openssl` |
| `Get-PSDrive` 的 Free/Used 失效 | 返回空或 `0` | `DriveInfo.AvailableFreeSpace` |

第三条最阴：它**返回 0 而不是报错**。第一次跑的时候 T4 提示词写的是 `(Get-PSDrive C).Free`，子代理会老老实实报「0.0 GB」并且 `status: ok`——一份看起来干净、实际上全错的报告。发现后中止重跑，把提示词改成 `DriveInfo`。

**教训：提示词里必须写清「本环境哪些 API 不可用、用什么替代」。子代理不会替你做能力探测，它只会照着提示词跑。**

## 这个实验没有证明什么

- **没测 n > 4**。8 路、16 路的加速比是推断，不是本次数据。
- **没测 token 成本**。并行省的是墙钟和父上下文，但 4 个子代理各自都在烧 token。本实验只测时间。
- **没测长上下文下的隔离收益**。串行组的后段变慢提示了这部分存在，但没有量化。
- **样本仍然小**。3 轮 × 2 组，中位数能挡住单轮噪声，挡不住系统性偏差。
